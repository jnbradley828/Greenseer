NEXT STEPS: "tune" feature split
=================================

Problem: reading params from the TOML at runtime (OnceLock) costs ~6-8% NPS,
because the compiler can no longer bake the values into the code.

Fix: one switch decides where ep()/sp() get their values. Call sites don't change.

  cargo build --release                  -> consts baked in from TOML at compile time (full speed)
  cargo build --release --features tune  -> TOML read at startup into OnceLock (for tuning)


1. Cargo.toml
   Add:
       [features]
       tune = []

2. build.rs (new file, repo root, next to Cargo.toml)
   - Read eval_heuristics.toml and search_heuristics.toml.
   - Write a generated file (baked_params.rs) into Cargo's build folder containing:
         const EVAL: EvalParams = EvalParams { field: value, ... };
         const SEARCH: SearchParams = SearchParams { field: value, ... };
   - Tell Cargo to rerun it whenever either TOML changes.

3. params.rs
   - Default build (#[cfg(not(feature = "tune"))]):
         include!(...baked_params.rs)
         ep() returns &EVAL, sp() returns &SEARCH
         initialize_params() is empty
   - Tune build (#[cfg(feature = "tune")]):
         keep the current OnceLock versions of ep(), sp(), initialize_params()

4. Verify
   - Release-build node counts at fixed depth should match main exactly.
   - NPS should be back to main's level.

5. Clean up
   - Delete eval_heuristics.rs and search_heuristics.rs (and their mod.rs lines).
     The TOML files are the only source of values from then on.
